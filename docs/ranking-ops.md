# 企画展ランキング 運用メモ

開催日は **`lib/config/festival.ts`** の開始・終了。  
対象: スタンプラリーと同じクラス・学科展 / 有志展示  
位置づけ: **当日の楽しみ**。公式表彰・賞品・ふくびき・誘導の根拠には使わない。待ちは来場者が見た並びの目安。票が無いブースは「空いている」ではなく情報なし。

接続文字列・パスワード・スタンプトークンは、このメモにもチャットにも書かない。Git にも入れない。

テンプレートの `data/ranking/snapshot.json` は空です。開催前の票は入っていません。

---

## 触ってよいもの / 触ってはいけないもの

### 当日まで・当日中に変えない

| 項目 | 理由 |
| --- | --- |
| `STAMP_TOKEN_MAP` と NFC/QR の URL | タグを書き直すまでスタンプが無効になる |
| `STAMP_SIGNING_SECRET` | 既存スタンプの署名が全部壊れる |
| Neon の **Auth** | このサイトでは使わない。オフのまま |
| Neon の CLI 手順（`neon.ts` / `neon deploy`） | 本リポジトリの構成と合わない |
| コンピュート **Max を 0.25 より大きくする** | 無料枠をすぐ消費する |
| Scale to zero をオフ（常時起動） | 開催月に 24 時間起こし続けると無料枠超過の原因 |
| ランキングを表彰・ふくびきの判定に使う | 仕様外。同じ人が何度も投票できる |
| `npm run db:push` の安易な再実行 | スキーマを変えていないなら不要 |
| `stamp:generate-tokens --force-rotate` | 全 NFC が無効になる |
| `MICROCMS_WEBHOOK_SECRET` の **Rotate Variable** | Vercel だけ変わると署名がずれ、企画・お知らせの更新が届かなくなる。回すなら祭のあと、microCMS のカスタム通知と同時 |

### 設定しておく（準備期間）

- Neon: コンピュート **Min = Max = 0.25 CU**
- Neon: **Scale to zero オン**（無料プランはオフにできない。オンのまま）
- Neon: Connection pooling **オン** の接続文字列（ホスト名に `-pooler`）
- ローカル `.env.local` と Vercel に `DATABASE_URL`（pooled）
- テーブル作成（`npm run db:push`）
- 開催中だけ `RANKING_ENABLED=true`。準備中は未設定か `false`

Vercel の `DATABASE_URL` は開催前に入れておいてよい。スタンプは DB なしでも動く。

開始時刻より前の `/ranking` は **「集計期間外です」**。時刻は `festival.ts` の `start`（日本時間）。

## 開場前にやること

リハーサルの票が総合に残らないよう、開場前に行だけ消す。

総合（`ranking_votes`）は期間で切らない。来訪は直近 20 分、待ちは直近 15 分だけなので、夜の行は開始時刻のトレンドと待ちには出ない。開始を空にするため、**3 つとも行を消す**。

1. Neon → **Tables** → `public`
2. `ranking_votes`、`ranking_visits`、`ranking_waits` の **行だけ** を消す。テーブル自体、列、インデックスは消さない
3. `npm run db:push` は実行しない
4. 消すのは開場前の最後にする。消したあとにスマホで星を送ると、その行は総合に残る

端末のスタンプ帳（LocalStorage）とは別物。行を消しても、獲得済みスタンプは端末に残る。

## 当日

1. 3 テーブルの行が空であることを確認する
2. `RANKING_ENABLED=true` で本番を出す
3. 開始時刻のあとに、スマホの本番サイトで次を通す
   - ナビ「企画情報」に **リアルタイムランキング** がある
   - `/ranking` が「集計期間外」でも「開催期間外」でもなく、順位の画面になる
   - NFC/QR → スタンプ帳のモーダルで星・待ち（またはスキップ）。`/ranking` へは飛ばない
   - 星を送った企画が `/ranking` の総合に出る。画面の更新は 60 秒ごと
4. 会場で見せるなら本番オリジンの `/ranking` を開く（専用モニターページは無い）

当日中にやらなくてよいこと:

- テーブルの作り直し
- Neon のコンピュートを大きくする
- トークン再生成
- 順位が「正確な人気投票」に見えるよう調整すること（仕様上そうならない）

当日に起きうる正常な現象:

- DB が Idle のあと、最初のアクセスだけ数秒遅い（起き上がり）
- 同じ企画を短時間に連打すると投票できない（約 30 秒）
- 同じ人が何度か星を入れると、その人の票が多く乗る
- Cookie 削除や端末を変えると別の来場者として扱われる

障害の切り分け:

| 症状 | まず見ること |
| --- | --- |
| 開始前に「集計期間外」 | 正常。`festival.ts` の開始時刻 |
| ナビにランキングが無い | Vercel の `RANKING_ENABLED` と再デプロイ |
| 開始後に「開催期間外」 | 同上。フラグが `false` |
| 投票できないがスタンプは残る | 投票失敗は仕様どおりスタンプ優先。Neon が起きているか、`DATABASE_URL` |
| スタンプ自体が失敗する | ランキングではなく `STAMP_TOKEN_MAP` / microCMS |

## 文化祭が終わったら

1. 手元の `.env.local` に `DATABASE_URL` がある状態で `npm run ranking:export` を実行し、`data/ranking` をコミットする
   → 票・来訪・待ちを JSON にする。来場者 ID はファイル内の連番に置き換わる
2. Vercel の `DATABASE_URL` を外して再デプロイ
   → 読み取りは `data/ranking/snapshot.json`。投票 API は 503。Neon は起きない
3. 順位の画面を残すなら `RANKING_ENABLED` は `true` のまま。ナビごと消すなら外すか `false`
4. 来年 `DATABASE_URL` を戻せば、同じ送受信コードが Neon に繋がる。前年の行を残したままにしない
5. コンピュートを大きくしたままだったら **0.25 に戻す**

`storageKey`（`festival.ts` の `stamp.storageKey`）は年度が変わると別キーになる。前年のスタンプ帳とは混ざらない。

## 数字（変えない前提）

| 項目 | 値 |
| --- | --- |
| `/ranking` の更新 | 60 秒 |
| トレンドの窓 | 直近 20 分 |
| 待ちの窓 | 直近 15 分（線形時間荷重。段階は自動で下げない） |
| 来訪のデバウンス | 同一人×企画 10 分に 1 回 |
| 投票の連打防止 | 同一人×企画 約 30 秒 |
| 総合スコア | ベイズ平均（事前平均 3.5、事前票数 8） |
| 待ちの段階 | すぐ入れる / 少し待ちそう / 並びがある / かなり待ちそう |

定数の置き場: `lib/config/rankingConfig.ts`。開始時刻だけ `lib/config/festival.ts`。
